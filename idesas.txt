=== 2. FEATURES ===
[feature] Share-to-XtoGram intake
  Share from the X app, choose XtoGram, the link is read, the card is generated with the
  default template.
  - Needs a share-intent library and a dev build; it does not work in Expo Go.
  - A shared item contains text with an x.com or t.co URL; extract the URL, then reuse
    the normal fetch flow.
  - Open: what if the user is signed out and out of guest generations?

[feature] "Post to Instagram" hand-off (no connection to Instagram, nothing is posted)
  [research] Instagram has no public API that opens the Reels editor with prefilled media.
  Likely options, each to be verified against current Instagram behaviour before building:
  - Stories: a Stories share intent takes a background image; the editor offers music and
    stickers.
  - Feed: the system share sheet; multiple images only on some platforms.
  - Reels: needs a video, so the cards would have to be rendered into a short video first.
  [decision] Which of Stories, Feed or Reels is the target? This decides the whole feature.

[feature] Font choice with on-demand download
  - Fonts are downloaded by the user and stored on the device; none are bundled.
  - Thumbnail cache keys must include the font.
  - Layout depends on font metrics, so planPages must re-run when the font changes.
  - Check licences before offering any font for download.
  [research] Check Devanagari/Hindi and emoji rendering in the current font setup.

[feature] Edit text and add/remove photos in the Content tab (step 7f)
  - Edits are kept as overrides keyed by tweet id (also for quoted tweets); the server
    data is never changed, and "Reset" deletes the override.
  - After an edit the page plan re-runs, so a longer text splits into more pages by itself.
  - [decision] Photos currently belong to a tweet and land on its last page. "Add images
    on any card" needs per-page media instead. Decide which model before building.
  - [decision] "Edited" mark on exported cards (recommended).
  - Add a clause to the Terms of Service: users are responsible for what they create and
    must not misrepresent others. Have a lawyer check the wording.

[feature] Background image and blur for carousel pages (the single framed card has it; the
      controls are hidden in multi mode).
[feature] "Continued" marker between the text pages of a split tweet.
[bug] A big photo plus a quote that has its own big photo can overflow the last page.
[debt] A single long tweet that becomes a carousel loses the frame toggle and advanced editor.
[feature] Share a whole series (the system share sheet takes one file at a time; needs a
      multi-file share library).
[debt] A reply to a stranger that starts a self-thread is treated as a chain, so the
      tweets below it are missed.

=== 5. KNOWN BUGS AND TECH DEBT ===
TransformableView and the card frame
[bug] Pinch pivots at the frame centre, not at the fingers (needs focal-point math).
[bug] reset() returns scale to 1, not to the fit scale (initialFrameScale).
[bug] Preview and export blur can differ: the preview uses RN blurRadius, the export a
      Skia sigma that is not multiplied by exportScale.
[debt] Gesture objects are recreated every render; wrap in useMemo.
[debt] The offscreen surface in renderFramedImage is not disposed after export.
[done/mitigated] The view covers the whole frame; one finger now scrolls, two move the card.

Recent templates
[debt] useRecentTemplates is called in both EditSheet and TemplatesTab (two separate states
      that can drift; storage is written twice). Call it once and pass it down, or use Context.
[debt] The recentTemplates useMemo is duplicated in both files; share one helper.
[debt] recordTemplateUsed writes to SecureStore inside a setState updater (should be pure).
[debt] SecureStore is meant for secrets; swap to AsyncStorage or MMKV.

Layout
[bug] FRAME_WIDTH / PREVIEW_WIDTH are computed once from Dimensions at import, so rotation
      and split screen don't update them. Use useWindowDimensions.
